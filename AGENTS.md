# Neovim Configuration Guide

This repository is a personal Neovim configuration written in Lua. Keep changes
small, readable, and compatible with the existing setup.

## Repository layout

- `init.lua` bootstraps `lazy.nvim`, imports plugin specs from `lua/`, selects the
  colorscheme, and loads options, keymaps, and custom commands.
- `lua/<feature>.lua` files normally contain one Lazy plugin spec or one focused
  configuration module.
- `lua/vim_options.lua`, `lua/keymaps.lua`, and `lua/custom_commands.lua` expose a
  `setup()` function and are loaded explicitly by `init.lua`.
- `lazy-lock.json` is generated by Lazy and pins plugin versions. Do not edit it
  manually.

## Change conventions

- Preserve the surrounding Lua style; do not reformat unrelated code.
- Add a new plugin in a focused module under `lua/`, then import that module in
  `require("lazy").setup()` in `init.lua`.
- Use lazy-loading triggers such as `event`, `cmd`, `ft`, or `keys` when they fit
  the plugin. Avoid lazy-loading changes that alter expected startup behavior.
- Put general keymaps in `lua/keymaps.lua`; keep plugin-specific mappings in the
  plugin spec when they are needed to load that plugin.
- Include a short `desc` on new keymaps and check for conflicts before choosing a
  mapping.
- Prefer current Neovim APIs. Keep an older-version fallback only when the code
  already supports one or the task explicitly requires it.
- Never commit credentials, tokens, machine-specific secrets, or generated cache
  files.

## Working safely

- The worktree may contain the owner's unfinished changes. Inspect `git status`
  first and do not overwrite, revert, or clean unrelated edits.
- Do not run plugin upgrades, `Lazy update`, Mason installs, or lockfile refreshes
  unless the user asks for dependency changes.
- For a focused fix, inspect the relevant module and its import or caller before
  editing. Avoid broad refactors unless requested.

## Validation

After changing Lua configuration, run the narrowest useful checks:

```sh
nvim --headless "+lua assert(loadfile('init.lua'))" +qa
```

When the change affects startup or plugin wiring, also run:

```sh
nvim --headless +qa
```

Report plugin download, external executable, or network failures separately from
Lua/configuration errors. Do not update `lazy-lock.json` merely to make a check
pass.

## Codex integration

- The Neovim plugin spec lives in `lua/codex_setup.lua` and is imported by
  `init.lua`.
- `<leader>cc` is the established mapping for opening Codex. Avoid defining the
  same mapping in multiple places.
- The integration expects the `codex` CLI to be available on `$PATH`.
